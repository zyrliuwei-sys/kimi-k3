<GuideSection id="what-is-kimi-k-3-1" number="01" title="What is Kimi K 3.1?">

**Kimi K 3.1** is a spaced search spelling of the Kimi K3.1 model family from Moonshot AI. Its first released model is **K3.1 Pro**, a successor to Kimi K3. It supports text and image understanding and a context window of up to one million tokens. [Official introduction](https://www.kimi.com/en/blog/kimi-k3-1-pro).

The useful distinction is between a model and the application around it. K3.1 Pro supplies reasoning; Kimi’s products provide the files, tools, and workspace used to complete a task. A request to understand a codebase, investigate a topic, or develop a 3D scene therefore depends on both the model and the selected environment.

<GuideCallout label="THE TAKEAWAY">
  Give it a defined deliverable, relevant material, and a way to check success.
  A larger context window is most useful when the task actually needs that
  context.
</GuideCallout>

</GuideSection>

<GuideSection id="capabilities" number="02" title="What can you use it for?">

Moonshot highlights improvements in programming, 3D creation, financial research, and longer agent workflows. These are the areas emphasized in its [release announcement](https://www.kimi.com/en/blog/kimi-k3-1-pro); they are not a guarantee that every task will succeed.

- **Understand and change software.** Provide a repository, explain a reproducible problem, and ask for a focused change with verification. Kimi Code offers file reading, editing, and command execution through desktop, CLI, and VS Code clients. [Client overview](https://www.kimi.com/code/docs/en/).
- **Work across substantial source material.** Use a research brief to connect documents, extract evidence, and identify disagreements. Specify which sources count and ask the model to distinguish evidence from assumptions.
- **Develop a 3D idea.** Describe the scene, geometry, constraints, and expected output in a Kimi environment with the necessary creation tools. Check the exported result in its intended viewer.
- **Turn analysis into a deliverable.** Ask for a structured comparison or a model with explicit assumptions. Check calculations and trace conclusions back to supplied material before relying on them.

</GuideSection>

<GuideSection id="get-started" number="03" title="Choose the right starting point">

**For general work**, start at [official Kimi](https://www.kimi.com/), check the available models, and submit one small, representative task. **For programming**, use [Kimi Code](https://www.kimi.com/code/docs/en/), open the relevant project, and select an available K3.1 Pro model. **For your own application**, use the [Kimi API platform](https://platform.kimi.com/).

The release announcement lists `kimi-k3.1-pro` and `kimi-k3.1-pro-highspeed` for the Open Platform. Kimi Code documents `k3.1-pro` and `k3.1-pro-highspeed`. Follow the documentation for your service; a similar name does not make the configurations interchangeable.

Begin with a noncritical task you can evaluate yourself. Keep the input and expected outcome so you can compare later runs. This is more informative than an impressive demonstration with unfamiliar material.

</GuideSection>

<GuideSection id="pricing" number="04" title="Pro or Highspeed? Know the tradeoff.">

Highspeed is positioned as the faster variant. Moonshot reports approximately 2–3× inference speed with the same model quality.² For API use, its published input and output rates are twice the standard Pro rates.

<GuideSection id="better-prompts" number="05" title="Give the model a finish line">

An effective prompt names the goal, available evidence, constraints, and required output. For programming, include reproduction steps and an acceptance check. For research, define the date range and source quality. For document analysis, ask for page references rather than an unsupported summary.

Try the same brief twice before expanding the task. Look for missing evidence, inconsistent calculations, and incomplete output. When revising, identify the specific failure instead of simply asking for a “better” answer. Keep a short checklist of recurring issues; it becomes a useful evaluation set for future model changes.

</GuideSection>
