## Kimi K3.1 in one sentence

Kimi K3.1 is widely expected to be an iteration of Kimi K3, which launched on July 16, 2026 as the largest open-weights model to date at 2.8 trillion parameters. The leaks suggest an evolution rather than a rebuild: the same tokenizer and chat format, with the focus on long-horizon agent tasks, reasoning efficiency, and reliability. Think of it as a refinement, not a new architecture.

## From K2 to K3: Moonshot’s release rhythm

In July 2025 Moonshot open-sourced Kimi K2 (1 trillion total, 32 billion active parameters), which drew wide attention in the open-source community for its agentic coding. The K2 line kept shipping incremental updates: as of mid-October, Moonshot’s API still serves kimi-k2.6 and the coding-focused kimi-k2.7-code. On July 16, 2026, K3 pushed the scale to 2.8 trillion parameters, and the full weights and technical report followed eleven days later.

Following the K2 pattern, “major release, then a point release a few months later” is Moonshot’s usual cadence. K3 is now three months old, so a K3.1 fits that rhythm.

The hardest evidence is Moonshot’s own website code and API registry. They show that “K3.1” exists internally — but say nothing about how strong it is or when it ships.

## Why it matters

After K3 launched, developer feedback clustered around three points: response speed, token spend during reasoning, and reliability on long tasks. If K3.1 keeps the capability of a 2.8T model while cutting reasoning overhead, open weights become an even stronger value for coding agents, deep research, and long-document analysis. The brokerage report and the leaked configuration point the same way: longer, more autonomous multi-step work.

Sparse MoE is how K3 stays “big but affordable”: 2.8 trillion parameters in total, yet each token touches only about 3.7% of them. Other official details:

- **Attention:** Kimi Delta Attention plus Attention Residuals; Moonshot claims about 2.5× K2’s scaling efficiency.
- **Numerics:** MXFP4 weights and MXFP8 activations; the full weights are about 1.56 TB across 97 shards, with 64+ accelerator supernodes recommended.
- **Reasoning:** thinking is always on; reasoning_effort accepts low, high, or max (default max).
- **Fixed sampling:** temperature 1.0 and top_p 0.95 — other values return an error, so check your client defaults.
- **Pricing:** $3 input and $15 output per million tokens; $0.30 for cached input.

## Rumored capabilities

- **Three reasoning tiers:** Low for cost, Max for quality. The K3 API already exposes the same three tiers, so this may not be new; one single-source report mentions an added medium tier.
- **Million-token context:** internally labeled “Extra Long”, matching K3’s 1,048,576 tokens.
- **Agents and multi-agent work:** the config lists Agent, Swarm, search, and batch modes. Kimi already supports Swarm, so these switches may be integration work rather than new capability.
- **Other rumors:** a “make3d” mode in the web code and a coding-specific variant — all single-source.

## What it means for developers

If K3.1 really keeps K3’s tokenizer and chat format, migrating should be cheap. Three things worth doing now:

1. **Make the model ID a config value.** When K3.1 ships, a one-line change rolls it out gradually, and a bad result rolls back in seconds.
2. **Tier calls by reasoning_effort.** Use low for simple classification and extraction, max for complex coding and research — it noticeably cuts reasoning tokens and latency.
3. **Do the real cost math.** At K3 rates, a request with 20,000 input tokens and 2,000 output tokens costs about $0.06 + $0.03 = **$0.09**. If that 20,000-token system prompt is cached, the input share drops to about $0.006. For long prompts, caching matters.

## Frequently asked questions

### Has Kimi K3.1 been released?

Not yet. As of October 23, there is no official model card, weights, or pricing.

### When will it be released?

Reports point to mid-to-late October, but earlier predictions have already slipped. Wait for the official announcement.

### How much will it cost?

Not announced. A preview listing reportedly showed K3 pricing, which may be a placeholder.

### Will I need to change code to switch from K3?

The tokenizer and chat format are reportedly unchanged, so a new model ID may be enough — but run a regression evaluation before switching.

### Will K3.1 be open weights?

K3 is open weights, and one leak claims K3.1 will follow, but that is single-source with no official commitment.
